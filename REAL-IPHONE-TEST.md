# Real iPhone acceptance check

This checklist can be completed without an orientation walk. Test from a safe location and treat every campus pin as approximate.

- [ ] Safari offers **Add to Home Screen** with **Open as Web App**.
- [ ] The Home Screen icon launches in standalone presentation.
- [ ] The private setup code imports only after preview and confirmation.
- [ ] The schedule survives closing and reopening the app.
- [ ] Current or next class, full building, room, and campus time are readable at normal and enlarged text sizes.
- [ ] No location prompt appears on launch, reload, onboarding, or Settings.
- [ ] A Directions tap triggers the one-time location permission flow.
- [ ] A second explicit tap opens the standard campus route.
- [ ] The campus map's own location control can enable its blue dot after permission.
- [ ] Apple Maps opens a walking route.
- [ ] Google Maps opens a walking route.
- [ ] The building and room remain visible in the app before external handoff and when returning.
- [ ] Denying location presents last-building, approximate-home, and destination-only choices as applicable.
- [ ] A low-accuracy result presents Try Again and explicit fallback choices.
- [ ] An off-campus result does not silently send the live origin to campus wayfinding.
- [ ] After one online load, airplane-mode reload still displays the schedule and clearly says external routing needs internet.
- [ ] Installing an available app update does not erase the imported schedule or provider preference.

Desktop browser automation cannot prove real iPhone GPS accuracy, iOS permission persistence, standalone-versus-Safari storage behavior, external-app handoff, Concept3D route quality, or live blue-dot behavior. Record those results only after this checklist is run on the target iPhone.
